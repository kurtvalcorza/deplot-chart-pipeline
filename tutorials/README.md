## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/deplot_chart_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 8-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True` and `trust_remote_code=False` through `Pix2StructForConditionalGeneration`/`Pix2StructProcessor`. The upstream `pytorch_model.bin` is not listed and not used. **The header font is supplied by the carried module** (`header_font_bytes`, Pillow's bundled Aileron) so the upstream processor's inference-time download of `ybelkada/fonts/Arial.TTF` never happens; the notebook's only external dependencies are the pinned PyPI distributions and the Hub at the model revision.
- **Role stages:** `validate_inputs` writes `outputs/deplot_chart_input_manifest.json` with the schema (fixed instruction, header rendering, patch budget, output conventions, decoding rule), the ceilings, the input's observed mode and size, the budget, the verdict, and one recorded rejection finding from the zero-budget probe; `evaluation_report` writes `outputs/deplot_chart_evaluation_report.json` — `sample-sanity` with a `cell_accuracy` entry (matched/total, both shapes) and a `title_match` entry on the synthetic chart; `not-measurable` on BYOD (with what labelled data would make the task measurable).
- The default sample is a deterministic 800×520 bar chart drawn in code with Pillow's bundled font from the five-row `EXPECTED_TABLE`, with every value printed above its bar — the same chart the smoke run used; `cell_accuracy`/`title_match` against data you rendered yourself are sanity evidence for the input contract, header rendering, forward pass, decoding and parsing, not a chart-to-table metric. The chart digest depends on the Pillow build's bundled font rendering and is printed, not asserted.
- Score semantics (UNC1–UNC4): the table is generated text with no score, probability or correctness signal; the notebook says so before the first extraction and again in the interpretation section, and states that a blank image still yields a table (an invented two-row table in the smoke run). The token budget is a caller-owned request parameter exposed as a `# @param` value (default `DEFAULT_MAX_NEW_TOKENS = 512`) and passed explicitly on every `extract_table` call; the instruction is fixed by the model's training and is not a parameter; `truncated` is surfaced and explained. The notebook performs no validation of its own — image and budget are checked only by the pipeline's `validate_inputs`/`extract_table` path.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PATCHES` (2048), `MAX_NEW_TOKENS` (1024), `DEFAULT_MAX_NEW_TOKENS` (512), `DECODING`, `INSTRUCTION` and the two separators are printed before the model runs.
- CPU is documented as adequate (card-measured 5.4 s load, 6.3 s per 800×520 chart at 56 generated tokens; 4.1 s for a blank image at a 64-token budget); the notebook states that cost scales with the tokens generated and that GPU output need not match CPU output token-for-token.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
