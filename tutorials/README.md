## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) extracted the table of one bar chart drawn in code and reported cell accuracy against the table you drew yourself as sample-sanity evidence, because no labelled chart set was bundled. This notebook keeps that chart and its inference contract as Section 5 and adds the adaptation contract around it: a real labelled corpus (one pinned SynthChartNet shard, converted to the model's own output convention and split by chart type), chart-to-table metrics and three non-neural baselines in the carried `metrics.py`, a bounded fine-tuning of the decoder, a per-chart-type breakdown, the drawn chart re-extracted after adaptation, and an artifact that reloads. The per-chart `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`). Whether the frozen model beats the empty table and whether the adapted model beats the frozen one are recorded as `frozen_beats_empty` and `adapted_beats_frozen`, not asserted, until a measured run is on file.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry before `torch` is imported; `DePlotPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`) and refuses a processor that is not the VQA variant; the header is rendered with Pillow's bundled font, so the Hub font the upstream processor would fetch is never downloaded. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `pyarrow`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample is one object in the Hub dataset repository `docling-project/SynthChartNet` at the immutable revision `b913ef98a3d45f6136465963ddc71a7a6b0e1728` (`train-00000-of-00135.parquet`, 515,825,444 bytes, 14,568 charts), downloaded whole and refused unless its size and SHA-256 equal the pins in `samples.py`; `fetch_corpus` refuses to run at all while no SHA-256 pin is recorded (`tools/pin_corpus.py` records it). Each chart type is shuffled with the seed and each split receives its share of the shard's type mix; a chart whose image digest was already drawn is skipped, and `check_split_disjoint` asserts no shared image.
- **Target format:** decided from the frozen checkpoint's own outputs on charts of this shard, not assumed, and documented in `samples.py`: bar, pie and stacked-bar OTSL tables carry the axis categories along their first row and are transposed to one row per category; line tables already hold one row per x point and are kept; `<ecel>` becomes an empty cell; `TITLE | ` comes first; cells are joined by ` | ` and rows by ` <0x0A> ` (which tokenises to the byte token the model emits).
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `target_from_otsl` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation) → `validate_inputs` + `pipe.extract_table` with sanity checks + `evaluation_report` on the drawn chart (inference contract) → `empty_baseline` + `header_only_baseline` + `medoid_baseline` + `pipe.evaluate` on the frozen model with the per-chart-type breakdown (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.extract_table` + `evaluation_report` on the drawn chart again (inference) → `pipe.save_artifact` → `DePlotPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the table is generated text with no score, probability or correctness signal; cell accuracy is position-wise, so RNSS (layout-free) is reported beside it; a blank image still yields a table; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the empty, header-only and medoid baselines and the frozen model are scored on the same test charts as the adapted model, overall and per chart type; every metric is labelled as one seeded split of one shard with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded, stratified by chart type and image-disjoint; validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that charts from few source documents must be split by source.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PATCHES` (2048), `MAX_NEW_TOKENS` (1024), `DEFAULT_MAX_NEW_TOKENS` (512), `MAX_TARGET_TOKENS` (512), `MAX_TARGET_CHARS` (512), `DECODING`, `INSTRUCTION`, the two separators and the record bounds (8..5,000) are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (names flattened, no `extractall`) and its records flow through the same validation, image-disjoint split, baselines, fine-tuning, evaluation, export and reload cells; the training split is written to `outputs/deplot_chart_train.jsonl` in the JSONL shape.
- Licence: the weights are Apache-2.0 and SynthChartNet is CDLA-Permissive-2.0 (use and sharing permitted, no restriction on trained results, attribution required); the notebook, README, card and `docs/WEIGHTS.md` say so, and the export records the corpus repository, revision, file pin, licence and target rule under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
